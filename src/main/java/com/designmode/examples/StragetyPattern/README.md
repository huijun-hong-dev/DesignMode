# 策略模式 (Strategy Pattern)

## 场景引入

你刚学完简单工厂，想想这个场景——

支付系统里，不同支付方式的选择逻辑用工厂解决了。但现在来个新需求：
不同支付方式，计算手续费的规则不一样。支付宝收 0.6%，银行卡收 0.1%。

## 什么是策略模式？

工厂模式解决的是 **"创建哪个对象"**；策略模式解决的是 **"怎么做某件事"**（算法/行为可以互换）。

**核心思想**：定义一系列算法，把它们封装起来，让它们可以互相替换，客户端不关心用的是哪个。

一句话：**行为的多态切换。**

## 结构

```
┌────────────────────┐
│  Context           │◄──── 上下文（OrderService）
│  - strategy        │         持有策略接口
│  + execute()       │         把活委托给策略
└────────┬───────────┘
         │ 持有
         ▼
┌────────────────────┐
│  Strategy (接口)   │◄──── 所有算法都实现这个
│  + calculate()     │
└────────┬───────────┘
         │
    ┌────┼────┬──────────┐
    ▼    ▼    ▼          ▼
┌────────┐┌────────┐┌────────┐┌────────┐
│Alipay  ││Wechat  ││CardPay ││ApplePay│
│Strategy││Strategy││Strategy││Strategy│
│+calc() ││+calc() ││+calc() ││+calc() │
└────────┘└────────┘└────────┘└────────┘

```

- **Strategy (接口)**：`FeeStrategy` — 所有手续费算法实现这个接口
- **ConcreteStrategy**：`AlipayFeeStrategy`、`CardFeeStrategy` — 具体算法
- **Context**：`OrderService` — 持有策略接口，把计算委托给策略

## 简单工厂 vs 策略模式

| 对比项 | 简单工厂 | 策略模式 |
|--------|----------|----------|
| 解决什么 | 创建哪个对象 | 用哪种算法/行为 |
| 客户端拿到后 | 直接调用对象的方法 | 委托给策略执行 |
| 关注点 | 对象的“出生” | 对象的“行为” |
| 典型代码 | `Factory.create()` | `context.setStrategy()` |


**工厂管“生”，策略管“干”。**

## 什么时候该用

✅ 同一件事有多种做法，客户端需要动态切换  
✅ if-else / switch 里根据类型选不同行为  
✅ 算法/规则会持续增加或变化  
✅ 想让算法独立于使用它的客户端变化  

❌ 就一种做法，永远不变 → 别用，直接写  
❌ 行为差异很小，只是参数不同 → 传参数就行，不用拆策略


## 现实类比

你去快递站寄东西。顺丰、中通、圆通都是“寄快递”这件事的不同策略。你选哪家（`setStrategy`），快递站就按那家的规则算价、走流程。快递站本身不关心具体怎么送，它只管“委托给选中的那家干”。
